# DEEPSTATOR

Независимое издание длинных текстов. Статический сайт: статьи хранятся в Markdown, сайт собирается в готовые HTML-страницы. Сервер, база данных и CMS не нужны.

## Что внутри

| Страница | Возможности |
|---|---|
| Главная `index.html` | Hero с манифестом, главный текст, новые тексты, цитата из статей, темы со счётчиками, избранное, блок «об издании» |
| Архив `archive.html` | Полнотекстовый поиск, фильтр по теме и тегу, «только избранное», сортировка (новые / ранние / по названию), счётчик, подсветка совпадений, фрагмент из текста, пустое состояние, «Показать ещё» (по 12), фильтры сохраняются в URL (`?category=…&tag=…&q=…`) |
| Статья `articles/<slug>.html` | Индикатор прочтения, оглавление (на десктопе закреплено сбоку с подсветкой текущего раздела, на мобильных сворачивается), время чтения и число слов, «осталось ~N минут», буквица, якоря у заголовков, цитаты, схемы, предыдущая/следующая, похожие тексты, копирование ссылки, системное «Поделиться» (если его нет, ссылка копируется), кнопка «наверх». У научной статьи есть шапка (УДК/ББК, аннотация, ключевые слова, English abstract), ссылки вида [5] ведут к списку литературы |
| Поиск (оверлей) | `Ctrl/⌘ K` или `/`, поиск по заголовкам, подзаголовкам, темам, тегам и полному тексту. Стрелки — выбор, Enter — открыть, Esc — закрыть. Индекс подгружается при первом открытии |
| Об издании `about.html` | Текст из `content/pages/about.md`. Плейсхолдеры `[[…]]` подсвечены, чтобы было видно, что заполнить |
| 404 `404.html` | Собственная страница ошибки |
| SEO | Уникальные title/description, canonical, Open Graph и Twitter, JSON-LD (`Article` / `ScholarlyArticle`), `sitemap.xml`, `robots.txt`, `rss.xml`, семантическая иерархия заголовков, адреса из транслита заголовков |

**Интерактивные функции** (работают в браузере читателя, без сервера и регистрации; данные хранятся в localStorage этого браузера):
- **Настройки чтения:** размер текста, гротеск или антиква, ширина колонки, тёмный фон или «Бумага». Запоминаются.
- **Сохранённое:** кнопка «Сохранить» в статье, счётчик в шапке, фильтр «Сохранённые» в архиве (`archive.html?status=saved`).
- **История чтения:** сайт помнит, где вы остановились. На главной есть блок «Продолжить чтение», на карточках — полоски прогресса, в архиве — фильтр «Непрочитанные / Начатые / Прочитанные».
- **Цитаты:** выделите текст в статье — появятся кнопки «Копировать цитату» (текст + название + ссылка) и «Поделиться».
- **Увеличение схем** по клику, «Случайный текст» (сначала непрочитанные), облако тегов и сортировка по длине в архиве, всплывающие уведомления.
- **Мобильная панель статьи:** оглавление, настройки текста, сохранить, поделиться и полоса прогресса.
- **Горячие клавиши** (справка — `?`): `Ctrl/⌘ K` или `/` — поиск, `R` — случайный текст, `G H` / `G A` — главная / архив, `[` `]` — соседние тексты, `B` — сохранить, `A` — настройки чтения, `T` — наверх.

Доступность: skip-link, видимый фокус, ARIA у диалога, меню, оглавления и живых счётчиков, клавиатурная навигация, `prefers-reduced-motion`. Все страницы читаются и работают без JavaScript (кроме поиска и фильтров).
Производительность: чистый HTML, один CSS (~51 КБ, ~10 КБ в gzip) и один JS (~29 КБ). Картинки — WebP + JPEG в двух размерах с `srcset` и lazy-loading.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev        # сборка + локальный сервер http://localhost:4321 + пересборка при изменениях
npm run build      # продакшен-сборка в dist/
npm run preview    # раздать готовый dist/
```

## Как добавить статью

1. `npm run new -- "Заголовок статьи"` создаст `content/articles/zagolovok-stati.md` с шаблоном. Можно и просто скопировать любой существующий файл.
2. Заполните шапку (frontmatter) и напишите текст в Markdown:

```yaml
---
title: Заголовок
subtitle: Подзаголовок-лид            # необязательно
excerpt: Анонс для карточек            # необязательно, иначе берётся первый абзац
category: Экономика                    # одна из site.config.ts (новые добавятся сами)
tags: [банки, бюджет]
date: 2026-10-24                       # дата публикации; пусто — дата не показывается
updated:                               # дата обновления, необязательно
language: ru
featured: false                        # true — в «Избранное»; самый новый избранный станет главным
cover: my-cover.jpg                    # файл из content/media/
coverAlt: Описание картинки
draft: false                           # true — не публикуется
---
```

3. Картинки положите в `content/media/`. Размеры и WebP сборка сделает сама. В тексте: `![Описание](my-image.jpg "Подпись")`.
4. `## Заголовок`, `### Подзаголовок` и строки целиком из **жирного** текста (`#### …`) попадают в оглавление. `> текст` — цитата, `---` — разделитель. Список литературы: заголовок `## Список литературы` и нумерованный список. Ссылки вида `[3]` в тексте станут кликабельными сами.

Время чтения, число слов, оглавление, номер текста, похожие статьи, поисковый индекс, RSS и sitemap считаются автоматически.

## Авторы

Авторы описаны в `content/authors.yml`, их фотографии лежат в `content/authors/`:

```yaml
richard-volkov:
  name: Ричард Волков
  photo: richard-volkov.jpg
ivan-petrov:            # новый автор
  name: Иван Петров
  photo: ivan-petrov.jpg   # квадратное или вертикальное фото, лицо по центру
```

В статье укажите `author: ivan-petrov` или просто имя. Фото и имя автора выводятся в шапке статьи, в карточке «Автор текста» в конце, на карточках главной и архива, в поиске и на странице «Об издании». В архиве есть фильтр по автору (`archive.html?author=ivan-petrov`). Если фото нет, показываются инициалы.

## Подписка и новые публикации

- **Колокольчик в шапке** показывает, сколько текстов вышло с прошлого визита читателя. Новые тексты отмечены меткой «Новое», в архиве есть фильтр «Новые с прошлого визита». Всё это работает в браузере читателя, без сервера.
- **Окно «Новые публикации»** (колокольчик, меню, подвал) предлагает способы подписки. RSS работает всегда (`rss.xml`).
- **Письма на почту.** Заведите бесплатный аккаунт на buttondown.com, подключите к нему RSS сайта (функция «RSS-to-email» — рассылка уйдёт сама при каждой новой статье) и впишите имя пользователя в `site.config.ts → subscribe.email.buttondown`. Появится форма подписки.
- **Telegram.** Ссылку на канал впишите в `subscribe.telegram` — появится кнопка.

Настоящие push-уведомления в браузере требуют собственного сервера, поэтому не реализованы.

## Страницы авторов

У каждого автора есть страница `authors/<id>.html`: большой портрет, статистика и все тексты. Портрет берётся из `content/authors/`; в `authors.yml` поле `focus: [x, y]` задаёт положение лица в процентах — по нему вырезается круглая аватарка. Можно добавить `bio:` — короткий текст под именем.

## Как снять статью с публикации

Добавьте в шапку статьи `draft: true`. Файл останется в проекте, но на сайт не попадёт. Так сейчас снят «Креационизм».

## Как поменять бренд

- **Тексты, URL, меню, рубрики, контакты, автор** — `site.config.ts`. Манифест на главной — `hero.statement`, слово в `*звёздочках*` выделяется красным курсивом.
- **Цвета, шрифты, ширина колонки, отступы** — `src/styles/tokens.css`.
- **Шрифты** подключаются из Google Fonts (Cormorant Garamond — заголовки, Manrope — интерфейс и текст, IBM Plex Mono — метаданные; у всех есть кириллица). Ссылка — в `src/components/ui.tsx` (`<link rel="stylesheet" …>`). Чтобы хранить шрифты у себя, положите woff2 в `public/fonts/` и замените ссылку на `@font-face` в `tokens.css`.
- **Соц-картинка** по умолчанию — `public/og-default.png` (`node scripts/og-image.mjs`). У статей с обложкой в соцсетях показывается обложка.
- **Страница «Об издании»** — `content/pages/about.md` (каждый заголовок `##` — отдельный блок). Блок «Авторы» строится сам.
- **Анимации** — `src/styles/motion.css` и `src/client/motion.ts`. При системной настройке «уменьшить движение» они отключаются полностью.

## Публикация

`npm run build`, затем выложите папку `dist/` на любой статический хостинг. Сейчас по умолчанию указан адрес `https://deepstator-site-1.onrender.com`. Если адрес другой, перед сборкой укажите его: `SITE_URL=https://ваш-домен npm run build` или поле `url` в `site.config.ts`. От него зависят canonical, sitemap, RSS и Open Graph.

- **Netlify / Cloudflare Pages:** команда сборки `npm run build`, папка `dist`, переменная `SITE_URL`.
- **Vercel:** Framework “Other”, Build `npm run build`, Output `dist`. Для адресов без `.html` добавьте `vercel.json` с `{"cleanUrls": true}`.
- **GitHub Pages:** соберите с `BASE_PATH=/имя-репозитория/` (нужно только для 404) и опубликуйте `dist/`.

Все внутренние ссылки относительные, поэтому сайт работает в подпапке и даже при открытии `dist/index.html` с диска.

## Что требует отдельной настройки

- Домен и `SITE_URL` (сейчас стоит заглушка `deepstator.example`).
- Контакты и биография на странице «Об издании» (сейчас плейсхолдеры).
- Админки нет. Статьи редактируются как файлы. Самый простой визуальный вариант — подключить репозиторий к Decap CMS или Pages CMS: они редактируют те же Markdown-файлы через браузер. Это не реализовано.
- Подписка на рассылку, комментарии и аналитика не реализованы.

## Стек и почему не Next.js

Проект собирался в изолированной среде без доступа к npm-реестру, поэтому Next.js и Tailwind установить и протестировать было невозможно. Вместо непроверенного кода на Next.js сделан собственный небольшой генератор на тех же технологиях: TypeScript + React (JSX-шаблоны рендерятся на этапе сборки), Markdown через `marked`, esbuild для клиентского кода, sharp для картинок, иконки Lucide (`react-icons/lu`). Стили — CSS с дизайн-токенами вместо Tailwind.
Результат — чистый статический HTML без клиентского фреймворка: это лучший вариант для Core Web Vitals. Контент (`content/`) полностью отделён от вёрстки. Если позже понадобится Next.js, Markdown-файлы и компоненты переносятся почти без изменений.

```
content/articles/   статьи (.md)
content/media/      исходные картинки
content/pages/      страница «Об издании»
site.config.ts      настройки сайта
src/build.tsx       сборка
src/pages/          шаблоны страниц
src/components/     общие компоненты (шапка, подвал, поиск, карточки)
src/client/         клиентский JS (поиск, архив, статья)
src/styles/         CSS (tokens.css — палитра и шрифты)
public/             копируется в dist как есть
```

Список импортированных и проблемных файлов — в `CONTENT_INVENTORY.md`.
